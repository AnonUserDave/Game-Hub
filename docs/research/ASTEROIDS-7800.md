## Reconstructed rules

- `$D000–$D2AE`: title, selection, attract and play branches; source menu repeat/direction/Select selection; separate pause/reset edge history. Mode bytes are `$FF` single, `$00` alternating, `$01` simultaneous team and `$02` simultaneous competition. Difficulty indexes remain 0–3. The [original Atari manual reproduction](https://atariage.com/manual_html_page.php?SoftwareID=2117) establishes their user-facing names and controller directions; selected code remains authoritative where behavior differs.
- `$D32C–$D62C`: ordered right/left turning, authored heading image, source thrust tables/speed comparisons, fractional carried-byte damping, firing/release latch and hyperspace. Four ship shots are shared in standard play; simultaneous play assigns two to each player. Two additional slots belong to the saucer. The supplied dual-button input path is preserved separately; its relation to the manual and actual controller electrical reads still needs comparison.
- `$D6B3–$DA8A`: source entry, respawn, hyperspace disappearance/random reentry/failure, death/end and winner phases. Alternating play swaps each player's 24 asteroid objects and retained wave/speed state. Source reserve counts and timed transitions are retained; obscure terminal/winner interactions and message drawing remain unqualified.
- `$F7F7–$F8F8`, `$F407–$F439`: ordered wave eligibility/delay, carried byte caps/timers, edge spawning and speed growth. Decorative-star refreshes consume their 24 source random samples even though this core does not yet present the starfield.
- `$F29C–$F3A9`: 16-bit fixed-point motion, original integer seam replacements with retained fraction, saucer X seam exception, source asteroid spin masks/ranges and projectile lifetimes. `$DA4F` advances explosions and defers the parent asteroid's count decrement until its authored final frame.
- `$DA92–$DDD9`: authored X/Y/diagonal collision extents and ship-outline points, seams, owner-shot exclusions, team ship bounce and competition damage; `$DD15–$DD8C` splits larger rocks, including Novice shrinking and the source Expert extra-child condition. The normal non-ship hit path is ported and tested. The original iterative virtual-point pair order and rare simultaneous-ship edge cases have not been compared and must not be described as proven equivalent.
- `$DE41–$DEB4`: original BCD award values, per-player and team scores, 10,000-point bonus-life carry and speed effect. `$F510–$F760` supplies saucer entry, size selection, motion, directed/random shots and aim jitter.

The implementation has no CPU instruction dispatcher, firmware executor, MARIA interpreter, floating-point genre physics or common-edition substitute. Native game state has fixed object pools, source arithmetic, version/source-bound Codable snapshots and bounded queued sound/rule events. A corrupt saved RNG rejection cycle stops with an explicit fault instead of inventing a random value or hanging the hub.

## Startup and timing boundaries

`Asteroids7800Startup` **requires** an existing 256-byte RNG RAM page, timer byte and provenance. Reset copies only 55 code bytes into `$2100`; the first second-index can read 55–62 before those bytes have been initialized by this cartridge routine. Native initialization therefore has no zero-filled production default. The tests expressly label their page synthetic. The title setup also consumes the source's initial 24 starfield RNG samples. A real original startup RAM/timer observation, or an owner-approved explicitly synthetic development mode, is still needed for integration.

The optional high-score cartridge service checks `$3900` and calls `$3FF7/$3FFA/$3FFD`; those firmware bytes are not supplied. The core signals that boundary and keeps its native source score state. It neither executes the calls nor claims firmware parity. Cross-mode high-score service/UI behavior remains open.

`displayInterrupt()` and `advanceMainPass()` are separate APIs. `$D063` masks the source DLI counter even and waits for a delta of two. The authored 51-byte DLL contains one DLI flag per frame. `tick` therefore advances two display interrupts and one main game pass. The [Atari 7800 Software Guide reproduction](https://7800.8bitdev.org/index.php/7800_Software_Guide) documents display interrupt and zone semantics; this implies roughly 30 main passes/sec on nominal NTSC. The carrier declares region 0, but header declarations and static instruction order do not prove the supplied runtime's actual cadence, DMA interruption or region. No processor speed is used as a game clock. Original timing and pause/attract details remain unqualified.

## Graphics API

Object coordinates are source integer high bytes plus low fractional bytes. An object's `image` and `palette` select frame key `objects-<two-digit image hex>-<32-(palette&31)>`; widths 1/2/3 decode to 4/8/12 logical pixels. Child rocks change width through the original palette/width byte. Frames use reverse page rows from `$C000–$CFFF`, with 160A 2-bit color indexes and transparency at zero. Original option/title graphics use `menu-<image hex>-<width>` from `$E000–$EFFF`; authored menu placement/palette tables are present. Original indirect score characters use `glyph-1` through `glyph-23` (four-by-eight pixels).

These are decoded original color indexes, not qualified RGB images or complete display lists. Holey-DMA padding, overlapping priorities, wrapped copies, colors, starfield, title/option/high-score layouts, HUD composition and sound output still need native presentation and source-frame comparison. Sound identifiers are queued; the authored sound stream/TIA output is not yet implemented.
