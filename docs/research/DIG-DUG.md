# Dig Dug: supplied C64 revision and native reconstruction

The selected T64 program is `DIG DUG+`, a packed release with a crack intro and
the `JACK ALIEN/REMEMBER` four-option trainer. Static decoding now recovers its
24,490-byte body. **There is no native Dig Dug gameplay module yet.** Content
recovery, source-derived native gameplay and a completed faithful rewrite remain
separate claims. All work here was performed on the son's M5 Pro / 24 GB /
macOS26.3. Original-game comparison, physical-controller checks and sustained
M1 Air / 8 GB / 2560×1600 acceptance remain unverified.

## Packed format reconstruction

The first loader copies `$46B2..$47B1` to `$0340..$043F`, then copies the footer
`$47A8..$48A7` to `$0723..$0822`. The second copy overlaps the loaded program's
header. The backward stream reaches that altered header, so decoding the
unmodified file alone is incorrect. The tool combines only these known ranges.

The relocated `$03CA` reader consumes MSB-first bits backward, initially using
the footer's bit byte. `$041C` selects count-table rows using unary bits and
uses index bit4 as the format end marker. `$0353` copies literal runs; `$0363`
selects match lengths, four-bit short offsets or a 13-row distance table with
an escape at offset122. `$03BF/$040D` copy matches into a descending output.
The output contains6,660 literal and16,384 match bytes. Invalid widths,
unwritten back-references, truncated bits and output overflow are rejected.

The intro's `$11DC/$14C0` path relocates `$1680` onward to `$0801`. Its page loop
also copies RAM beyond the known intro. The decoder retains only the19,333
bytes actually recovered; it never fills the unknown remainder with guessed
zeroes. The second loader relocates descending pages to high RAM. Its stream
at `$B4FB` corresponds to the known source at `$0882`, so none of the unknown
intro RAM is needed for the selected packed stream.

The second `$00FD` reader advances that stream; `$0111..$0153` decodes five
markers: `$E2` counted repeated bytes, `$E7` three repeated bytes, `$D6` counted
zeroes, `$CB` one zero and `$C7` counted spaces. A count of0 means256. Two
overlapping `BIT` instructions skip the short-run/count-increment alternatives;
the assembly, rather than misleading decompiler output, determines those paths.
All19,204 known stream bytes decode into the body above. The source's final
pointer-wrap path jumps to the trainer before returning a value from `$FFFF`;
the decoder needs no guessed byte at that address.

## Trainer and actual game boundary

`$7090` shows intro pages and enters the trainer. Four optional choices patch
unlimited lives (`$A1DF`), monster hits (`$B179/$B22A/$B2CF/$B2EB`), rock hits
(`$AB51/$AB55`) and Commodore-key level skipping (`$80C3`). **The preparation
tool applies none of those patches.** This preserves the supplied default
bytes; it does not establish that this trainer revision equals a pristine
commercial release.

The trainer installs an18-byte helper at `$0340`, fills `$0800..$5FFF`, then
jumps to `$8000`. The game initializes its native source state, VIC/CIA and
firmware dependencies and continues to the `$A094` entry/selection path.
`$8086..$820E` contains a foreground dispatcher with pause/input handling,
movement, action, draw and interrupt-count waits. This is a research map, not
an implemented lifecycle. Runtime reconstruction must resolve the installed
helper, raster/interrupt schedule, joystick/keyboard semantics and source tables
directly in native code without running the machine code.

## Evidence, checks and next work

REA opened the actual archive and identified ZIP metadata/hash. Raw6502 imports
are not supported by this REA provider, so relocated loaders and recovered code
were analyzed with direct Ghidra12.1.2's `6502:LE:16:default` profile and the
hash-fenced first-party `ExportAsteroids.java` script. Those static records are
**not REA Evidence**, source code or original runtime observations. The
headless analysis uses a768MiB heap and two compiler/GC threads; none of it is
a shipped runtime dependency.

Six Python tests pass on M5: synthetic marker/literal/match semantics, zero-byte
counts, escaped marker values, malformed operands, distance/width/extent bounds
and the complete selected-media size/hash chain. Preparation also passes.

```sh
python3 Tools/prepare_retro_media.py
python3 Tools/decode_dig_dug.py
python3 -m unittest Tests.test_dig_dug_decode -v
```

Next: reconstruct the game/interrupt scheduler, source level/terrain/entity
tables, pump/inflation, monster/rock/bonus rules, original graphics/audio,
player/mode transitions and title-specific saves; integrate a bounded native
session; record original behavior/visual/audio comparisons and physical-input
checks; finish every M1 acceptance gate. No `verified` or playable registry
